# Стартовий код — ЛР5 (dead_log)

Опис структури стартового каркаса. Каркас навмисно НЕ компілюється — студент виправляє коди
помилок, а не пише проєкт з нуля.

## Структура каталогу
```
dead_log/
├── Cargo.toml
└── src/
    ├── main.rs
    ├── level1_ownership.rs   # навмисна помилка E0382 (move + повторне використання)
    ├── level2_lifetimes.rs   # навмисна помилка через відсутню анотацію часу життя
    └── level3_refactor.rs    # компілюється, але містить зайві .clone() для оптимізації
```

Каркас лежить у каталозі поточної роботи навмисно: рівень 1 не має залежати від того, чи
виконана робота № 4. Рівні 2 і 3 у варіанті **A** працюють не тут, а в наскрізному ядрі —
у модулі `core/sidkit/src/logscan.rs` того самого crate, що створений у роботі № 4 (варіант
**B** — від знімка `vtfk-sid-reference@after-lab04`, у файлах цього каркаса).

## src/level1_ownership.rs — навмисна помилка рівня 1
Містить функцію `fn decode_fragment(log: String) -> String`, яка передає `log` у допоміжну
функцію за значенням, а потім намагається використати `log` вдруге:
```rust
pub fn decode_fragment(log: String) -> String {
    let decoded = process(log);       // log переміщується (move) у process
    format!("{} / оригінал: {}", decoded, log)   // помилка: log вже переміщено
}

fn process(s: String) -> String {
    s.to_uppercase()
}
```
Супровідний тест `decode_fragment_smoke` у `#[cfg(test)] mod tests` перевіряє, що після
виправлення функція повертає рядок, що містить і декодований, і оригінальний фрагмент.

## src/level2_lifetimes.rs — навмисна помилка рівня 2
Містить функцію без анотації часу життя, що повертає одне з двох вхідних посилань залежно від
довжини — компілятор не може вивести спільний час життя без явної анотації `'a`:
```rust
pub fn pick_longer_coordinate(a: &str, b: &str) -> &str {
    if a.len() >= b.len() { a } else { b }
}
```
Студент має додати коректну анотацію `'a`, щоб функція компілювалась і коректно відображала
залежність вихідного посилання від обох вхідних.

## src/level3_refactor.rs — ціль для рефакторингу (рівень 3)
Компілюється "як є" (з рівня 1–2, уже виправлених), але навмисно містить зайві `.clone()` на
кожному кроці обробки вектора рядків. Час виконання до і після рефакторингу вимірюється власним
таймером `std::time::Instant` (найпростіший варіант на стабільному toolchain). Якщо хочеш саме
`cargo bench` — врахуй, що вбудований bench-harness потребує nightly (`#![feature(test)]`); на
стабільному каналі підключи `criterion` у `[dev-dependencies]` і додай `[[bench]]` з
`harness = false` (напр. `benches/decode_bench.rs`).

## Що з'являється в ядрі (варіант A рівнів 2–3)
```
core/sidkit/
├── Cargo.toml               (з роботи № 4)
└── src/
    ├── main.rs              + рядок `pub mod logscan;`
    └── logscan.rs           НОВЕ: decode_fragment + pick_longer_coordinate<'a>
```
Імена функцій у `logscan.rs` збігаються з іменами в каркасі — тести й перевірки шукають ті самі
сигнатури незалежно від обраного варіанта.

## Заборонено змінювати
- Сигнатури публічних функцій `decode_fragment`, `pick_longer_coordinate` (окрім додавання
  анотацій часу життя) — на них спираються супровідні тести.
- Назви файлів модулів.

## Як здати

Здача — **тег**, а не пуш. Пуші безкоштовні й нічого не запускають; перевірка стартує на тезі
`submit/*`. Тег складає й ставить скрипт здачі, тож набирати нічого не треба:

**Ctrl+Shift+B** — або меню `Terminal → Run Build Task`, або з терміналу:

```bash
bash .devcontainer/submit.sh
```

Скрипт покаже незбережені зміни й запропонує їх закомітити, скаже, **який тег створить** і на
якому коміті, і спитає підтвердження. Відповідь `y` означає «здаємо»; будь-що інше, зокрема
порожній Enter, означає «ні» — і тоді не відбувається нічого, це не помилка.

Результат з'явиться у вкладці **Actions**, потім — у **Releases** цього репозиторію; оцінка й
коментар — у Feedback PR. Кожна перевірка звітує окремо, тож видно, що саме не зійшлося.

**Перездавати можна скільки завгодно разів**, доки відкритий модуль. Наступна здача — наступний
вільний тег (`submit/lab05-2`, `submit/lab05-3`); скрипт бере його сам, спитавши GitHub про вже
зайняті. Яка це робота, перевірка визначає за **іменем репозиторію**, а не за іменем тега, тож
номер у тезі ні на що не впливає.

**Запасний шлях.** Поза Codespaces скрипта немає — тоді ті самі дії руками:

```bash
git add . && git commit -m "lab05: рівень 1"
git tag submit/lab05
git push origin submit/lab05
```
