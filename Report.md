Відповіді на контрольні питання

1. Що означає код помилки E0382 і за яких умов компілятор його видає?
E0382 означає спробу використати значення після того, як володіння ним було переміщено (use of moved value). Компілятор видає цю помилку, коли змінна типу, що не реалізує трейт Copy (наприклад, String, Vec<T>), передається в іншу змінну або функцію за значенням (відбувається move), а потім програма намагається звернутися до старої змінної.

2. Чим E0502 відрізняється від E0499?

E0502 — конфлікт між незмінним (&T) та змінним (&mut T) запозиченнями одного й того самого значення одночасно (не можна мати активне &mut T, поки існує хоча б одне &T, і навпаки).

E0499 — спроба створити більше одного змінного запозичення (&mut T) одного й того самого значення одночасно (у Rust в один момент часу може існувати лише одне ексклюзивне посилання &mut T).

3. Що таке lifetime elision і який код помилки ти побачиш, коли компілятор не зможе застосувати його автоматично?
Lifetime elision (виведення / опускання часів життя) — це набір детермінованих правил у компіляторі Rust, за якими він автоматично підставляє параметри часу життя в сигнатури функцій, щоб розробнику не доводилося писати їх вручну в простих випадках.
Коли функція повертає посилання, а вхідних посилань кілька і компілятор не може однозначно визначити, з яким входом пов'язаний результат, він видає помилку E0106 (missing lifetime specifier).

4. Чи змінює анотація 'a реальний час життя значення? Що вона насправді повідомляє компілятору?

Ні, анотація 'a нічого не подовжує, не скорочує і не змінює в поведінці програми під час виконання (runtime). Вона лише описує зв'язок між уже наявними часами життя вхідних і вихідних посилань, допомагаючи borrow checker довести на етапі компіляції, що повернуте посилання не переживе дані, на які воно вказує (не стане висячим посиланням).

5. Наведіть приклад мінімальної зміни (без переписування логіки), яка усуває помилку E0382.
Якщо допоміжній функції потрібно лише прочитати рядок, замість передачі володіння String використовується запозичення &str:

Rust
// Було (E0382 при повторному використанні log):
fn process(s: String) -> String { s.to_uppercase() }
let decoded = process(log);

// Стало (запозичення без move і без копіювання):
fn process(s: &str) -> String { s.to_uppercase() }
let decoded = process(&log);

6. Чому .clone() — це часто "швидке", але не завжди найкраще виправлення конфлікту запозичень?

.clone() виділяє нову пам'ять у купі (heap) та копіює туди всі дані. Це маскує помилку проектування володіння замість того, щоб коректно передати посилання, що призводить до зайвих витрат пам'яті та процесорного часу (особливо у циклах і при обробці великих обсягів даних).

7. Що виводить команда rustc --explain <код> і чим вона корисна під час діагностики?

Команда виводить вбудовану офіційну довідку компілятора для конкретного коду помилки: детальне пояснення причини виникнення помилки, мінімальний приклад коду, який її викликає, та приклади правильного виправлення. Це допомагає швидко зрозуміти суть обмеження borrow checker без пошуку в інтернеті.

8. Як звуження області видимості запозичення блоком { } може усунути конфлікт E0502?

Блок { ... } створює окрему область видимості (scope). Коли посилання (&T або &mut T) створюється і використовується всередині фігурних дужок, при виході з блоку воно знищується і позика офіційно завершується. Після закриття блоку значення знову вільне для створення нового запозичення іншого типу без конфлікту.

9. Три ходи проти E0382 з таблиці вище — розстав їх за ціною для програми й скажи, чому .clone() останній.
Порядок від найдешевшого до найдорожчого:

1. Заміна типу параметра на запозичення (String → &str) — ціна: нуль (передається лише адреса та довжина, без алокацій).

2. Звуження області видимості блоком { } — ціна: нуль (суто конструкція для компілятора без накладних витрат у runtime).

3. Виклик .clone() — ціна: пам'ять і час (виділення пам'яті в купі та копіювання байтів).
.clone() стоїть останнім, оскільки це єдиний варіант із трьох, який несе реальні накладні витрати під час виконання програми, тоді як перші два вирішують проблему безоплатно на етапі компіляції.



Висновок
Під час виконання лабораторної роботи №5 було практично опрацьовано правила володіння та запозичення у Rust під контролем borrow checker. Було усунено помилку використання переміщеного значення (E0382) за рахунок незмінного запозичення &str, додано коректну анотацію часу життя 'a для вирішення E0106, а також прибрано зайві виклики .clone() під час обробки масиву рядкових фрагментів, зберігши коректність логіки та проходження всіх тестів.
